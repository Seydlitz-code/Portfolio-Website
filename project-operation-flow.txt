1. 프로젝트 개요
================================================================================

  본 프로젝트는 Node.js + Express 기반의 개인 포트폴리오 웹사이트이다.
  관리자가 게시물을 작성/관리하고, 방문자는 게시물을 열람하며 댓글을 작성할 수 있는
  블로그/게시판 형태의 웹 애플리케이션이다.

  주요 특징:
  - 한국어/일본어 이중 언어 지원 (게시물 제목, 게시판 이름)
  - SQLite (로컬 개발) / PostgreSQL (Railway 등 프로덕션) 이중 DB 지원
  - 관리자 게시물 에디터 (HTML contenteditable 기반 리치 텍스트)
  - 게시물 본문 내 이미지/비디오 첨부 (최대 55MB)
  - 프로필 이미지 업로드 (DB BLOB 저장)
  - 댓글 기능
  - 댓글 알림 시스템 (관리자 대상)
  - 회원가입/로그인 (세션 기반 인증)
  - CSS Scroll Snap 히어로 화면

2. 기술 스택
================================================================================

  [서버]
  - Runtime       : Node.js (>=18.0.0)
  - Framework     : Express 4.18
  - Template      : EJS 3.1
  - Database      : better-sqlite3 (로컬) / pg + PostgreSQL (프로덕션)
  - Session       : express-session (SQLite/PostgreSQL 스토어)
  - Auth          : bcrypt (비밀번호 해시)
  - File Upload   : multer (memoryStorage)
  - HTTP Method   : method-override

  [클라이언트]
  - CSS           : Pure CSS (style.css 단일 파일)
  - JS            : Vanilla JavaScript (ES5 호환, 모듈 미사용)
  - Icons         : Font Awesome 6.5.1 (CDN)
  - Fonts         : Google Fonts (Noto Sans KR, Inter)
  - 반응형        : CSS 미디어 쿼리 (768px 이하 대응)

4. 데이터베이스 스키마
================================================================================

  [DB 모드]
  - 로컬 개발: SQLite (better-sqlite3, 동기식)
  - 프로덕션 : PostgreSQL (DATABASE_URL 환경변수 감지 시 자동 전환)
  - lib/db.js가 두 DB를 추상화하여 동일한 비동기 인터페이스 제공
  - SQLite의 ? 플레이스홀더를 PostgreSQL의 $1, $2, ... 로 자동 변환
  - INSERT 시 RETURNING id를 자동 추가하여 lastInsertRowid 호환

  [테이블 목록]

  users                  # 사용자 테이블
  ├── id (PK, AUTOINCREMENT/SERIAL)
  ├── username (UNIQUE)      # 로그인 아이디
  ├── nickname               # 표시 닉네임
  ├── password               # bcrypt 해시
  ├── avatar                 # 아바타 이미지 경로 또는 URL
  ├── avatar_mime            # 아바타 MIME 타입
  ├── avatar_blob            # 아바타 이미지 바이너리 (DB 저장)
  ├── is_admin (0/1)         # 관리자 여부
  └── created_at

  projects               # 게시판/프로젝트 분류
  ├── id (PK)
  ├── name                    # 한국어 이름
  ├── name_ja                 # 일본어 이름
  ├── description             # 설명
  ├── order_num               # 정렬 순서
  └── created_at

  posts                  # 게시물
  ├── id (PK)
  ├── title                   # 한국어 제목
  ├── title_ja                # 일본어 제목
  ├── content                 # HTML 본문
  ├── project_id (FK)         # 소속 게시판
  ├── author_id (FK)          # 작성자
  ├── view_count              # 조회수
  ├── created_at
  └── updated_at

  comments               # 댓글
  ├── id (PK)
  ├── post_id (FK)            # 대상 게시물
  ├── user_id (FK)            # 작성자
  ├── parent_id (FK, self)    # 대댓글 (현재 UI 미사용)
  ├── content                 # 댓글 내용 (최대 100자)
  ├── created_at
  └── updated_at

  comment_notifications  # 댓글 알림
  ├── id (PK)
  ├── recipient_user_id (FK)  # 수신자 (관리자)
  ├── comment_id (FK, UNIQUE) # 알림 대상 댓글
  ├── post_id (FK)            # 대상 게시물
  ├── actor_user_id (FK)      # 댓글 작성자
  ├── read_at                 # 읽은 시간 (NULL=미확인)
  └── created_at

  site_settings          # 사이트 설정 (key-value)
  ├── key (PK)
  └── value

     기본 설정값:
     - site_name          : "Donghawan Lee / @lilip"
     - bio                : 자기소개 HTML (관리자만 편집)
     - profile_image      : 프로필 이미지 경로
     - all_posts_intro_ko : 전체 게시물 소개 (한국어)
     - all_posts_intro_ja : 전체 게시물 소개 (일본어)

  persisted_binaries     # 영구 바이너리 저장소
  ├── kind (PK)              # 식별자 (예: "site_profile_image")
  ├── mime                    # MIME 타입
  └── data                    # 바이너리 데이터

  post_body_assets       # 게시물 본문 첨부 미디어
  ├── id (PK)
  ├── mime                    # MIME 타입
  ├── data                    # 바이너리 데이터
  └── created_at

5. 서버 구동 흐름 (server.js)
================================================================================

  (1) Express 앱 생성
      - app = express()
      - PORT = process.env.PORT || 3000

  (2) 미들웨어 등록
      ┌─────────────────────────────────────────────────────────────┐
      │ app.set('trust proxy', 1)                                  │
      │ app.set('view engine', 'ejs')                              │
      │ → res.locals에 sanitizeSiteHtml, sanitizeBioHtml 등록       │
      │ → express.json()                                           │
      │ → express.urlencoded({ extended: true, limit: '12mb' })    │
      │ → methodOverride('_method')  ← PUT/DELETE 폼 지원          │
      │ → /media 정적 라우트                                        │
      │ → express.static('public') (CSS/JS: 캐시 비활성화)          │
      ├─────────────────────────────────────────────────────────────┤
      │ 세션 미들웨어 (buildSessionMiddleware)                      │
      │   ├── PostgreSQL 모드: connect-pg-simple 사용               │
      │   │     └── portfolio_session 테이블                        │
      │   └── SQLite 모드: better-sqlite3-session-store 사용        │
      │         └── data/sessions.db, journal_mode=WAL              │
      │   설정:                                                     │
      │     - name: 'portfolio.sid'                                │
      │     - maxAge: 7일 (1000*60*60*24*7)                        │
      │     - secure: production only                              │
      │     - sameSite: 'lax'                                      │
      ├─────────────────────────────────────────────────────────────┤
      │ 사용자 정보 로드 미들웨어                                    │
      │   → 세션에 user.id가 있으면 DB에서 nickname, avatar 조회      │
      │   → res.locals.user, res.locals.isAdmin,                    │
      │     res.locals.notificationUnreadCount 설정                  │
      │   → 모든 템플릿에서 전역 접근 가능                            │
      └─────────────────────────────────────────────────────────────┘

  (3) 라우트 등록
      ├── /auth          → routes/auth.js
      ├── /boards        → routes/boards.js
      ├── /posts         → routes/posts.js
      ├── /admin         → routes/admin.js
      ├── /mypage        → routes/mypage.js
      ├── /api           → routes/notifications.js
      └── /              → routes/posts.js (GET /) + 메인 렌더링

  (4) 메인 페이지 렌더링
      GET /
      → getSiteHomeData()
          ├── site_settings 테이블 전체 조회 → settings 객체
          ├── profile_image가 persisted_binaries에 있으면 URL 변환
          ├── 최근 게시물 5개 (posts + projects JOIN)
          ├── 프로젝트 목록 + 각 프로젝트별 최근 게시물 5개
          └── 반환: { settings, recentPosts, projects: [...withPosts] }
      → res.render('index', { ...home })

  (5) 404 / 500 에러 핸들러
      └── error.ejs 렌더링

  (6) start() 함수
      ├── initializeDatabase() 호출
      │     ├── PostgreSQL: initializePostgres() → 테이블 생성 + 마이그레이션
      │     └── SQLite: initializeSqliteSync() → 테이블 생성 + 컬럼 마이그레이션
      ├── 관리자 부트스트랩 (최초 1회)
      │     └── ADMIN_BOOTSTRAP_USERNAME, ADMIN_BOOTSTRAP_PASSWORD 환경변수로
      │         최초 관리자 계정 생성 (프로덕션에서 관리자 없으면 기동 중단)
      └── app.listen(PORT, '0.0.0.0')

──────────────────────────────────────────────────────────────────────────────
6.1. 인증 라우트 (routes/auth.js)  ─  /auth
──────────────────────────────────────────────────────────────────────────────

  GET /auth/login
  ├── 이미 로그인 상태면 redirect('/')
  └── login.ejs 렌더링

  POST /auth/login
  ├── username, password 검증
  ├── bcrypt.compareSync() 비밀번호 비교
  ├── req.session.user = { id, username, nickname, avatar, is_admin }
  ├── req.session.save() → 로그인 성공 시 redirect(이전 페이지 or /)
  └── 실패 시 login.ejs 재렌더링 (에러 메시지 포함)

  GET /auth/check-username
  └── AJAX용 아이디 중복 확인 (JSON 응답)

  GET /auth/check-nickname
  └── AJAX용 닉네임 중복 확인 (JSON 응답, 세션에 검증 상태 저장)

  GET /auth/register
  ├── 보안문자(captcha) 생성: 단순 덧셈 문제
  ├── req.session.captchaAnswer = 정답
  └── register.ejs 렌더링

  POST /auth/register
  ├── multer로 아바타 이미지 업로드 처리 (memoryStorage, 최대 3MB)
  ├── captcha 정답 확인
  ├── 비밀번호 확인, 길이 검증 (8~20자)
  ├── 아이디 중복 확인
  ├── bcrypt.hashSync(password, 12)
  ├── INSERT INTO users
  ├── 아바타 이미지가 있으면 DB BLOB 저장 + avatar 경로 업데이트
  └── 성공 시 redirect('/auth/login?registered=true')

  POST /auth/logout
  └── req.session.destroy() → redirect('/')

──────────────────────────────────────────────────────────────────────────────
6.2. 게시물 라우트 (routes/posts.js)  ─  /posts
──────────────────────────────────────────────────────────────────────────────

  GET /posts                          # 전체 게시물 목록 (페이지당 200개)
  ├── getSiteSettings() → site_name, intro 등 조회
  ├── 게시물 전체 카운트 → 페이지네이션 계산
  ├── posts + projects + users JOIN 조회 (global_num 포함)
  ├── 각 게시물에 display_time, title_ko_short, title_ja_short 등 추가
  └── posts.ejs 렌더링

  GET /posts/new                      # 게시물 작성 폼
  ├── requireAdmin 미들웨어
  ├── 프로젝트 목록 조회
  ├── editorInitJsonB64: 에디터 초기값 (base64 인코딩 JSON)
  └── post-form.ejs 렌더링

  POST /posts                         # 게시물 생성
  ├── requireAdmin 미들웨어
  ├── 프로젝트 선택 검증 (게시판 지정 필수)
  ├── 제목/본문 검증
  ├── sanitizePostHtml(content) → XSS 방지
  ├── INSERT INTO posts
  └── redirect('/posts/{id}')

  GET /posts/:id                      # 게시물 상세
  ├── posts + projects + users JOIN 조회
  ├── view_count 증가 (UPDATE +1)
  ├── 댓글 목록 조회 (comments + users JOIN, created_at ASC)
  ├── 수정 여부 판단 (updated_at - created_at > 2초)
  ├── postContentLooksLikeHtml → HTML 여부 판단
  └── post.ejs 렌더링

  GET /posts/:id/edit                 # 게시물 수정 폼
  ├── requireAdmin 미들웨어
  └── post-form.ejs 렌더링 (기존 값 채움)

  PUT /posts/:id                      # 게시물 수정
  ├── requireAdmin 미들웨어
  ├── sanitizePostHtml 후 업데이트
  ├── updated_at = CURRENT_TIMESTAMP
  └── redirect('/posts/{id}')

  DELETE /posts/:id                   # 게시물 삭제
  ├── requireLogin 미들웨어
  ├── 작성자 본인 또는 관리자만 삭제 가능

  └── redirect('/posts') 또는 마이페이지 작성글 목록

  POST /posts/:id/comments            # 댓글 작성
  ├── requireLogin 미들웨어
  ├── sanitizeCommentInput: NUL 제거, 개행→공백, 100자 제한, 위험 문자열 제거
  ├── INSERT INTO comments
  ├── createCommentNotification():
  │     └── 게시물 작성자가 관리자인 경우 알림 레코드 생성

  ├── requireLogin
  ├── 본인 댓글만 수정 가능
  └── updated_at = CURRENT_TIMESTAMP

  DELETE /posts/:postId/comments/:commentId # 댓글 삭제
  ├── requireLogin
  ├── 본인 또는 관리자만 삭제 가능

  POST /posts/body-upload             # 본문 미디어 업로드 (AJAX)

8. 보안 메커니즘
================================================================================

  [XSS 방지]
  ├── 게시물 본문: sanitizePostHtml()
  │     ├── <script>, <style> 태그 제거
  │     ├── on* 이벤트 핸들러 제거 (onclick, onerror 등)
  │     ├── javascript:, data:text/html 프로토콜 제거
  │     └── 관리자가 HTML을 직접 작성하므로 완전 차단은 아님 (신뢰 기반)
  ├── 자기소개: sanitizeBioHtml()
  │     └── sanitizePostHtml + 빈 블록 태그 제거
  └── 댓글: sanitizeCommentInput()
        ├── NUL 문자 제거
        ├── 개행 → 공백
        ├── 100자 제한
        ├── </textarea>, </script> 제거
        └── 서버/클라이언트 양쪽 검증

  [인증/인가]
  ├── requireLogin: 세션 없으면 /auth/login으로 리다이렉트
  ├── requireAdmin: is_admin != 1 → 403 에러
  ├── 게시물/댓글 수정/삭제: 작성자 본인 또는 관리자만 가능
  └── safeRedirectPath: 오픈 리다이렉트 방지 (/로 시작하고 //로 시작하지 않음)

  [세션 보안]
  ├── cookie.secure: production에서만 true
  ├── cookie.sameSite: 'lax' (CSRF 방지)
  ├── 세션 ID 별도 쿠키 이름: 'portfolio.sid'
  └── 세션 만료: 7일

  [파일 업로드 보안]
  ├── 화이트리스트: 이미지(JPG/PNG/GIF/WEBP), 비디오(MP4/WEBM/QuickTime)
  ├── 크기 제한: 프로필 3MB, 본문 55MB, 사이트 이미지 5MB
  ├── memoryStorage 사용 (디스크 저장 X)
  └── 모두 DB BLOB으로 저장 (배포 시 디스크 초기화 대응)

  [DB 보안]
  ├── SQL 인젝션: 매개변수화된 쿼리(? 플레이스홀더) 사용
  ├── 비밀번호: bcrypt hash (cost 12)
  ├── 관리자 부트스트랩: 소스에 비밀번호 하드코딩 없음 (환경변수만 사용)
  └── 프로덕션에서 관리자 없고 환경변수 없으면 기동 중단

11. 주요 설계 원칙 및 특징
================================================================================

  1. 이중 DB 지원 (lib/db.js 추상화)
     - SQLite ? 플레이스홀더 → PostgreSQL $1, $2 자동 변환
     - INSERT 시 RETURNING id 자동 추가
     - 모든 쿼리는 비동기 Promise 기반 (SQLite도 async로 래핑)

  2. 관리자 부트스트랩
     - DB에 관리자 계정이 없을 때만 환경변수로 최초 관리자 생성
     - 평문 비밀번호를 서버에서 bcrypt 해시하여 저장
     - 프로덕션에서 관리자 없으면 기동 중단

  3. 마이그레이션
     - SQLite: PRAGMA table_info로 컬럼 존재 여부 확인 후 ALTER TABLE
     - PostgreSQL: information_schema.columns 조회
     - 이전 버전에서 마이그레이션된 기존 post에 author_id 자동 할당

  4. 이중 언어 지원
     - 게시판 이름: name(한국어) / name_ja(일본어)
     - 게시물 제목: title(한국어) / title_ja(일본어)
     - 전체 게시물 소개문: all_posts_intro_ko / all_posts_intro_ja

  5. HTML Sanitize (허용 목록 기반이 아닌 제거 목록 기반)
     - 관리자 전용 게시물 에디터 → HTML 직접 입력 허용
     - 위험 태그/속성만 제거하고 나머지는 통과
     - 완전한 XSS 방지가 아닌 신뢰 기반 + 최소 방어

  6. 페이지네이션
     - 빌더 패턴: buildPaginationItems(current, total) → 중앙 생략형
     - 이전/다음 + 페이지 번호 + 말줄임(…) 생성
     - 게시물 목록: 200개/페이지, 마이페이지: 10개/페이지, 게시판 관리: 20개/페이지

  7. 세션 기반 인증
     - 로그인 시 req.session.user에 id, username, nickname, avatar, is_admin 저장
     - 모든 요청마다 미들웨어가 DB에서 최신 nickname, avatar 조회
     - 프로필 변경 시 세션 즉시 갱신

  8. 미디어 저장
     - 모든 업로드 파일은 DB BLOB으로 저장
     - 컨테이너/에페멀 디스크 초기화에도 데이터 보존
     - /media/* 경로로 서빙 (Cache-Control 헤더 포함)
